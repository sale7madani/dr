## نظرة عامة (Overview)

واجهة المطعم هي **شاشة الكاشير** التي يستقبل من خلالها المطعم الطلبات الواردة من تطبيق الزبون، ويديرها عبر مراحلها حتى تسليمها للكابتن (السائق). 

**المستخدم المستهدف:** كاشير المطعم — شخص مشغول وغير تقني. لذلك المبدأ التصميمي الحاكم:
- **زر واحد كبير** لكل بطاقة طلب يقوم بالإجراء التالي المنطقي.
- **خط كبير، أرقام واضحة، أقل نص ممكن.**
- **تنبيه صوتي + شاشة منبثقة** للطلب الجديد حتى لا يضيع أي طلب.
- **RTL بالكامل، عربي فقط.**

**الجهاز المستهدف:** كمبيوتر / شاشة كبيرة (سطح مكتب). التصميم أفقي بأعمدة.

**دور المطعم: جهة تنفيذ فقط** — لا يتعامل مع المدفوعات أو التوصيل لوجستياً؛ فقط يقبل/يرفض الطلب ويحضّره ويسلّمه للكابتن. (مهم: أسباب الرفض كلها متعلقة بقدرة المطبخ، لا بأمور مالية.)

### دلالة ألوان الحالات (Status Color Semantics)
- 🟡 **جديد (new)** → ذهبي `--gold`
- 🔵 **قيد التحضير (preparing)** → أزرق `--blue`
- 🟢 **جاهز للاستلام (ready)** → أخضر `--green`
- ⚪ **تم التسليم (delivered)** → رمادي `#bcb4a2` / `#c9c2b1`
- 🔴 **مرفوض (rejected)** → أحمر `--red`
- 🔴 **عاجل/متأخر (urgent)** → أحمر `--red` (يُطبّق فوق أي حالة عند تجاوز الوقت)

- **اتجاه:** `dir="rtl"` على مستوى `<html>`.

### الزوايا (Border Radius)
`--r-sm: 8px` · `--r: 14px` · `--r-lg: 20px` · `--r-xl: 28px`

### الظلال (Shadows)
- `--sh-sm`: `0 1px 2px rgba(23,21,15,.06), 0 1px 3px rgba(23,21,15,.05)`
- `--sh`: `0 2px 6px rgba(23,21,15,.06), 0 8px 20px rgba(23,21,15,.06)`

### المسافات (Spacing)
سلّم مبني على مضاعفات ~4px. حشوات شائعة: بطاقات `15–17px`، لوحات `22–24px`, فجوات الأعمدة `14–16px`.

### العملة (Currency)
- القيمة الحالية: **`₪` (شيكل)** — معرّفة في مكان واحد: `CURRENCY` في `data.js`.

- **كل الأسعار أعداد صحيحة صغيرة** (مثلاً 65, 48, 12). غيّر العملة من متغيّر واحد فقط.

## الشاشات والعروض (Screens / Views)

التطبيق **صفحة واحدة (SPA)** فيها قائمة جانبية ثابتة + منطقة محتوى تتبدّل بين 5 عروض رئيسية.

### التخطيط العام (App Shell)
- **القائمة الجانبية (Sidebar):** عرض `238px`، خلفية `--ink` (سوداء)، على **اليمين** (RTL). تحتوي:
  - الشعار (مربع ذهبي 42px بحرف «س» + اسم «سنبل» + اسم المطعم والفرع).
  - روابط التنقّل: الطلبات / المنيو / ملخص اليوم / الإحصاءات.
  - في الأسفل: رابط الإعدادات + **مفتاح «مفتوح/مشغول»** (toggle) لإيقاف استقبال الطلبات.
- **الشريط العلوي (Topbar):** ارتفاع `64px`، خلفية بيضاء، فيه الساعة الحية + حالة الاستقبال + زر كتم/تشغيل صوت التنبيه.
- **منطقة المحتوى:** تملأ المتبقّي، `flex:1`, `min-height:0` (مهم للسكرول الداخلي).

### 1) شاشة الطلبات (Orders) — الشاشة الرئيسية

**الغرض:** إدارة كل الطلبات الجارية عبر مراحلها.

**المكوّنات من الأعلى للأسفل:**
1. **شريط أدوات (`.ordertools`):**
   - **حقل بحث** (يملأ المساحة، حد أقصى 480px): يبحث في **اسم الزبون** أو **اسم الوجبة** أو **رقم الطلب** فورياً. فيه زر مسح (×) يظهر عند الكتابة.
   - **منتقي تاريخ** (`<input type="date">`, `max=اليوم`): يفلتر الطلبات حسب يوم الإنشاء.
   - **شريحة التاريخ المختار** (سوداء) مع زر إلغاء — تظهر فقط عند اختيار تاريخ.
   - **عدّاد النتائج** (يسار): «N طلب · نتيجة الفلترة».
2. **شريط التبويبات (`.filterbar`):** 6 تبويبات مع عدّاد لكل واحد:
   - `الكل` (يعرض لوحة الكانبان الثلاثية) · `جديد` · `قيد التحضير` · `جاهز للاستلام` · `تم التسليم` · `مرفوض`.
   - تبويب «جديد» ينبض ويتلوّن ذهبياً (كلاس `has-alert`) عند وجود طلبات جديدة.
   - الأربعة الأخيرة تعرض **شبكة بطاقات** (grid) للحالة المختارة بدل اللوحة.
3. **لوحة الكانبان (`.board`)** عند اختيار «الكل»: 3 أعمدة متساوية:
   - عمود **طلبات جديدة** (خلفية ذهبية خفيفة في الأعلى)، عمود **قيد التحضير**، عمود **جاهزة للاستلام**.
   - كل عمود: رأس (نقطة لون + عنوان + عدّاد) + جسم قابل للتمرير عمودياً (`overflow-y:auto`, `min-height:0`).

**بطاقة الطلب (`.ocard`) — أهم مكوّن:**
- شريط علوي ملوّن (5px) حسب الحالة.
- **رأس:** `#رقم الطلب` + «· N صنف» على اليسار، **مؤقّت** على اليمين.
- **اسم الزبون** بلون **ذهبي غامق** (`--gold-deep`) وزن 800، تحته أول جزء من العنوان.
- **قائمة الأصناف:** `×الكمية` (ذهبي) + اسم الصنف + التعديلات (مثل «بدون بصل») بخط أصغر باهت. تعرض حتى 3 أصناف ثم «+ N أصناف أخرى…».
- **ملاحظة الزبون** (صندوق ذهبي خفيف) — تظهر في حالة «جديد» فقط.
- **سبب الرفض** (صندوق أحمر) — يظهر في حالة «مرفوض».
- **التذييل:** «قيمة الطلب» + المبلغ (مجموع الأصناف فقط — **بدون رسوم توصيل، المطعم لا يراها**) + شارة طريقة الدفع.
- **زر الإجراء الكبير** (يملأ العرض، حسب الحالة):
  - جديد → «عرض الطلب وقبوله» (ذهبي) → يفتح المنبثقة.
  - قيد التحضير → «جاهز للاستلام» (أخضر).
  - جاهز → «سلّمته للكابتن» (أسود).
- **النقر على البطاقة** (خارج الزر): يفتح لوحة التفاصيل (أو المنبثقة إن كانت جديدة).
- **`flex-shrink: 0`** على البطاقة — مهم حتى لا ينضغط ارتفاعها عند تكدّس البطاقات.

**المؤقّتات (Timers):** تتحدّث كل ثانية:
- جديد → عدّاد `mm:ss` منذ الوصول. يتحوّل لتحذير (ذهبي) عند ≥2 د، وأحمر عند ≥4 د.
- قيد التحضير → «باقي N د» اعتماداً على وقت التحضير المختار؛ «قارب» (ذهبي ≤5 د)، «تأخّر N د» (أحمر) عند انتهاء الوقت.
- جاهز → «جاهز منذ N د» (أحمر بعد 6 د).
- تم التسليم → وقت التسليم (HH:MM ص/م).
- مرفوض → كلمة «مرفوض».

### 2) المنبثقة: طلب جديد وارد (New Order Modal)

**الغرض:** عرض كامل تفاصيل الطلب الوارد ليقرّر الكاشير قبوله أو رفضه.

**السلوك:** عند وصول طلب جديد → **يبدأ تنبيه صوتي متكرر** (كل 2.6 ثانية) + تظهر المنبثقة فوق كل شيء. الصوت يتوقف عند التعامل مع الطلب أو كتمه.

**المكوّنات:**
- رأس أسود مع جرس ذهبي يهتزّ (أنيميشن `ring`) + «طلب جديد وارد» + `#الرقم` + زر كتم الصوت.
- صفّ الزبون (اسم + هاتف) وصفّ العنوان.
- صندوق الأصناف (كل صنف: كمية + اسم + تعديلات + سعر السطر).
- ملاحظة الزبون (إن وُجدت).
- إجمالي قيمة الأصناف + شارة الدفع.
- **اختيار وقت التحضير التقديري:** 4 أزرار preset — `15 سريع` / `20 عادي` / `30` / `45 مزدحم`. الافتراضي من الإعدادات (`defaultPrep`).
- **التذييل:** زر «رفض» (أحمر مفرّغ) + زر «قبول الطلب · N دقيقة» (ذهبي، كبير).
- **النقر خارج المنبثقة** يغلقها (يبقى الطلب في عمود «جديد» للتعامل معه لاحقاً).

### 3) حوار رفض الطلب (Reject Dialog)

**الغرض:** اختيار سبب الرفض. **كل الأسباب متعلقة بقدرة المطبخ على التنفيذ فقط** (المطعم جهة تنفيذ — لا أسباب مالية أو لوجستية).

**المكوّنات:** رأس أحمر + قائمة أسباب (راديو) + خيار «سبب آخر…» يفتح حقل كتابة.
**الأسباب المعرّفة (`REJECT_REASONS`):**
1. صنف مطلوب غير متوفّر حالياً
2. المطبخ مزدحم — لا يمكن التحضير الآن
3. نقص في المكوّنات اللازمة
4. عطل في معدّات المطبخ
5. المطعم على وشك الإغلاق
6. حجم الطلب أكبر من طاقة التحضير الحالية
7. + «سبب آخر» (نص حر)

زر «تأكيد الرفض» (أحمر) يُفعّل فقط عند اختيار سبب. عند التأكيد → الطلب ينتقل لحالة `rejected` مع تسجيل `rejectReason` و`rejectedAt`.

### 4) لوحة تفاصيل الطلب (Order Drawer)

**الغرض:** عرض كل تفاصيل أي طلب (غير الجديد) + الخط الزمني.

**السلوك:** تنزلق من اليسار (`slidein`)، مع overlay يغلقها بالنقر.

**المكوّنات:**
- رأس: رقم الطلب + اسم الزبون + زر إغلاق.
- صندوق سبب الرفض (إن كان مرفوضاً).
- معلومات الزبون (هاتف، عنوان) + ملاحظة.
- جدول الأصناف الكامل (كمية + اسم + تعديلات + سعر).
- الإجمالي = **إجمالي الأصناف فقط** + شارة الدفع.
- **الخط الزمني (Timeline) — مطلوب صراحةً من العميل:** يعرض وقت كل مرحلة **ومدّتها**:
  - `وصل الطلب` (createdAt)
  - `قيد التحضير` (acceptedAt) — مع «استغرق قبوله · المدة»
  - `جاهز للاستلام` (readyAt) — مع «مدة التحضير · المدة»
  - `تسليم للكابتن` (deliveredAt) — مع «انتظار الكابتن · المدة»
  - في حالة الرفض: يعرض «وصل الطلب» ثم «تم رفض الطلب» (نقطة حمراء).
- تذييل بزر الإجراء التالي حسب الحالة.

> **تنفيذ:** خزّن طوابع زمنية (timestamps) منفصلة لكل انتقال حالة: `createdAt`, `acceptedAt`, `readyAt`, `deliveredAt`, `rejectedAt`. المدد تُحسب كفرق بين الطوابع.

### 5) شاشة إدارة المنيو (Menu)

**الغرض:** إدارة كاملة للأصناف والتصنيفات + إخفاء/إظهار النافذ.

**المكوّنات:**
- رأس: عدد التصنيفات/الأصناف/النافذ + بحث عن صنف + زر «تصنيف جديد» (أسود).
- لكل **تصنيف:** عنوان + عدّاد + أزرار: «إضافة صنف» (ذهبي مفرّغ)، تعديل الاسم (قلم)، حذف التصنيف (سلة، حمراء عند hover).
- لكل **صنف:** اسم + سعر + زر تعديل (قلم) + **مفتاح متوفّر/نفذ** (toggle). الصنف النافذ يظهر مشطوباً برمادي.

**محرّر الصنف (Item Editor Modal):** اسم + سعر (مع لاحقة العملة) + اختيار التصنيف (select) + الحالة (متوفر/نفذ) + زر حذف (للموجود). يتحقّق من صحّة الاسم والسعر.

**محرّر التصنيف (Category Editor Modal):** حقل اسم؛ يمنع التكرار.

**حوار حذف التصنيف (Delete Category Dialog) — مطلوب صراحةً:**
- رأس أحمر + تحذير: «سيتم حذف هذا التصنيف **وجميع أصنافه (N صنف)** نهائياً».
- يعرض عيّنة من أسماء الأصناف التي ستُحذف.
- **حقل تأكيد بالكتابة:** يجب كتابة **اسم التصنيف بالضبط** ليُفعّل زر «حذف نهائي» (مطابقة `text.trim() === cat`).

### 6) شاشة ملخص اليوم (Summary)

**الغرض:** لقطة سريعة لأداء اليوم الحالي.

**المكوّنات:** 4 بطاقات إحصاء (طلبات مكتملة، إجمالي المبيعات، متوسط وقت التحضير، طلبات مرفوضة) + لوحة «الأصناف الأكثر طلباً» (أعمدة) + لوحة «نظرة سريعة» (نقدي/أونلاين/متوسط قيمة الطلب/النافذ/صافي اليوم). الأرقام = قاعدة ثابتة + إضافات الجلسة الحية.

### 7) شاشة الإحصاءات (Analytics)

**الغرض:** مؤشرات أداء بصرية مع فلترة وتصدير.

**المكوّنات:**
- **شريط فلترة الفترة:** اليوم / 7 أيام / 30 يوم / مخصّص (نطاق تاريخين) — يعيد حساب كل المؤشرات.
- **زر تصدير (CSV):** يصدّر مجموعة البيانات المعروضة (الطلبات/المبيعات) كملف CSV قابل للفتح في Excel.
- **4 مؤشرات (KPIs):** مبيعات اليوم، عدد الطلبات، متوسط قيمة الطلب، متوسط وقت التحضير — كل واحد مع نسبة التغيّر مقابل أمس (سهم أخضر/أحمر).
- شريط رؤى (ساعة الذروة + أعلى يوم مبيعات).
- **مخطط أعمدة:** مبيعات الأسبوع.
- **مخطط مساحي (SVG، RTL):** الطلبات حسب ساعات اليوم، مع تحديد الذروة.
- **مخطط دائري (Donut، SVG):** توزيع طريقة الدفع (نقدي/أونلاين).
- **أعمدة أفقية:** الأكثر مبيعاً + الأقل مبيعاً.

> الشارتات مرسومة يدوياً بـ SVG (بدون مكتبة). في الإنتاج يمكن استخدام مكتبة (Recharts/Chart.js/ECharts) مع الحفاظ على نفس الدلالات والألوان واتجاه RTL.

---

### 8) شاشة الإعدادات (Settings)

**الغرض:** معلومات المطعم + مواعيد العمل + إعدادات الطلبات.

**المكوّنات:**
- **معلومات المطعم:** الاسم، الفرع، الهاتف.
- **مواعيد العمل:** لكل يوم من 7 أيام → مفتاح مفتوح/مغلق + وقت فتح + وقت إغلاق (`<input type="time">`).
- **إعدادات الطلبات:** الحد الأدنى للطلب، وقت التحضير الافتراضي، تفعيل/كتم صوت التنبيه.

## التفاعلات والسلوك (Interactions & Behavior)

- **التنبيه الصوتي:** يُولّد برمجياً بـ Web Audio API (بدون ملفات صوت) — نغمة جرس مزدوجة تتكرّر حتى التعامل مع الطلب. يحتاج تفاعل المستخدم أولاً لتفعيل `AudioContext` (سياسة المتصفحات). في التطبيق الأصلي (native) استبدله بصوت إشعار حقيقي.
- **وضع «مشغول»:** عند الإيقاف → بانر مخطّط في الأعلى + تعطيل استقبال الطلبات الجديدة.
- **النقر خارج المنبثقات** يغلقها؛ النقر داخلها لا (إيقاف propagation).
- **الأنيميشن:** ظهور المنبثقة (`pop`)، انزلاق اللوحة (`slidein`)، نبض التنبيه (`pulse`)، اهتزاز الجرس (`ring`). تُعطّل عند `prefers-reduced-motion`.
- **الحفظ التلقائي:** كل الحالة تُحفظ في `localStorage` (مفتاح `sunbul_restaurant_vN`) وتُسترجع عند التحميل. **في الإنتاج: استبدلها بـ API/قاعدة بيانات + تحديث لحظي (WebSocket/SSE) لاستقبال الطلبات من تطبيق الزبون.**

## إدارة الحالة (State Management)

**كائن الطلب (Order):**
```
{
  id,            // معرّف فريد (string)
  number,        // رقم العرض (يبدأ من 1042…)
  status,        // "new" | "preparing" | "ready" | "delivered" | "rejected"
  customer: { name, phone, address },
  items: [ { id, name, price, qty, mods: [String] } ],
  note,          // ملاحظة الزبون (String، قد تكون فارغة)
  payment,       // "cash" | "online"  (للعرض فقط — المطعم لا يحصّل)
  subtotal,      // إجمالي الأصناف (= المبلغ الذي يراه المطعم)
  // ملاحظة: delivery/grandTotal موجودة في البيانات لكنها لا تُعرض للمطعم
  createdAt, acceptedAt, readyAt, deliveredAt, rejectedAt,  // طوابع زمنية (ms)
  prepTime,      // وقت التحضير المختار (دقائق)
  rejectReason   // سبب الرفض (String)
}
```

**الانتقالات (State Transitions):**
- `new → preparing`: عند القبول؛ يسجّل `acceptedAt = now` و`prepTime`.
- `preparing → ready`: عند «جاهز»؛ يسجّل `readyAt = now`.
- `ready → delivered`: عند «سلّمته للكابتن»؛ يسجّل `deliveredAt = now` ويضيف للإحصاءات.
- `new → rejected`: عند الرفض؛ يسجّل `rejectReason` و`rejectedAt`.

**حالة عامة أخرى:** `accepting` (يستقبل/مشغول)، `menu` (التصنيفات والأصناف)، `settings`، `session` (عدّادات الجلسة).

**متطلّبات جلب البيانات في الإنتاج:**
- اشتراك لحظي بالطلبات الجديدة (push).
- مزامنة حالة المنيو والإعدادات مع لوحة التحكم/تطبيق الزبون.
- إرسال انتقالات الحالة + وقت التحضير للنظام (ليُحدّث الزبون والكابتن).

## ملاحظات أخيرة للمبرمج
1. **أكّد درجة الأصفر الرسمية** ورمز العملة مع العميل.
2. التصميم **Hi-Fi RTL** — التزم بالقيم بدقّة، واعكس كل الاتجاهات بشكل صحيح (`inset-inline`, `margin-inline`).
3. **مبدأ UX الحاكم:** زر واحد كبير لكل بطاقة + أقل احتكاك ممكن — لا تُضِف خطوات للكاشير.
4. استبدل `localStorage` بطبقة بيانات حقيقية + تحديث لحظي للطلبات الواردة.
5. الشارتات يدوية بـ SVG — يمكن اعتماد مكتبة في الإنتاج مع الحفاظ على الدلالات وRTL.
